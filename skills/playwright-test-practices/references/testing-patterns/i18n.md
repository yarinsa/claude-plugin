# Internationalization

## Locale as a project

```ts
projects: [
  { name: 'en', use: { locale: 'en-US', timezoneId: 'UTC' } },
  { name: 'he', use: { locale: 'he-IL', timezoneId: 'Asia/Jerusalem' } },
],
```

`locale` sets `Accept-Language` and `navigator.language`, which is what most apps negotiate on. If yours selects language by URL prefix or cookie, set that instead - assert the mechanism the app actually uses.

## Never assert translated strings

```ts
// Breaks in every locale but one
await expect(page.getByRole('button', { name: 'Save' })).toBeVisible();

// Locale-independent
await expect(page.getByTestId('save')).toBeVisible();

// Or resolve through the same catalog the app uses
await expect(page.getByRole('button', { name: t('actions.save') })).toBeVisible();
```

The `t()` form is better: it still exercises the accessible name, and a missing key fails loudly. Import the real catalog - never a copy.

## Catalog completeness

Cheap, high-value, and needs no browser:

```ts
test('no missing or empty keys', () => {
  const base = Object.keys(flatten(en));
  for (const [loc, cat] of Object.entries(catalogs)) {
    const keys = flatten(cat);
    expect(base.filter((k) => !(k in keys))).toEqual([]);      // missing
    expect(Object.entries(keys).filter(([, v]) => !v)).toEqual([]);  // empty
  }
});
```

Also assert no untranslated placeholder leaks to the UI:

```ts
await expect(page.getByText(/^[a-z]+(\.[a-z_]+)+$/)).toHaveCount(0);   // raw dotted keys
```

## RTL

```ts
test.use({ locale: 'he-IL' });

await expect(page.locator('html')).toHaveAttribute('dir', 'rtl');
```

Assert `dir` is actually set - the most common RTL bug is a translated app that never flips direction. Then check mirrored affordances: back/forward chevrons, progress direction, drawer side, and that icons which should *not* mirror (play button, clock) did not.

Numbers, code, and URLs stay LTR inside RTL text - a screenshot test on a mixed-direction paragraph is worth one baseline.

## Formatting

```ts
await expect(page.getByTestId('price')).toHaveText('1.234,56 €');   // de-DE
await expect(page.getByTestId('date')).toHaveText('15/03/2024');    // en-GB
```

Pin the clock and timezone first (`advanced/clock-mocking.md`), or these fail on the wrong day. Cover the separator swap (`1,234.56` vs `1.234,56`) and currency symbol position - both are frequent regressions when a formatter is hand-rolled.

Pluralization needs the zero/one/few/many cases for a language that has them; English-only testing hides the bug.

## Layout under expansion

German and Finnish run 30-40% longer than English. Assert no overflow rather than eyeballing:

```ts
const overflow = await page.evaluate(() =>
  document.documentElement.scrollWidth > document.documentElement.clientWidth);
expect(overflow).toBe(false);
```

Combine with a narrow viewport for the worst case. A pseudo-locale that pads every string is the cheapest way to surface this in one run.

## Scope

Run the full suite in the default locale. Run a small, targeted subset (layout, formatting, RTL direction) across locales - matrixing everything multiplies cost for very little added signal.
